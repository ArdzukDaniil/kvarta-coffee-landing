# Техническое описание

## Стек и почему

- **Фронт:** чистый HTML/CSS/JS без сборки, лежит в `public/`. Шрифты (Sofia Sans Extra Condensed, Commissioner) хостятся локально, фото в WebP.
- **Бэкенд:** Python + FastAPI, `app.py`. На Vercel это одна serverless-функция, `public/` раздаёт CDN. Next.js был бы плюсом, но я выбрал стек, код которого могу читать и защищать сам.
- **Почему не Render:** бесплатный сервис засыпает через 15 минут, и первый запрос ждёт 30–60 секунд. Проверяющий ждал бы сайт или ответ формы около минуты.
- **Хранилище — Turso (libSQL, SQLite в облаке).** SQLite-файл на Vercel не годится: файловая система функции временная, заявки терялись бы. Turso — тот же SQLite: SQL одинаковый локально и на проде, бесплатный тариф. Обращение идёт через HTTP API, без нативных зависимостей. Локально и в тестах используется обычный `sqlite3`.

## Форма и `POST /api/lead`

| Требование ТЗ | Решение |
|---|---|
| Белорусский номер | `kvarta/phone.py` приводит любой ввод (`+375…`, `8 029…`, `029…`) к `+375XXXXXXXXX`. Принимаются мобильные коды 25/29/33/44 и городские 15/16/17/21/22/23. Та же проверка есть в `main.js`, чтобы подсказка появлялась сразу, но решает сервер. Номер другой страны маска не переделывает: человек видит, что ввёл. |
| Повтор за 10 минут и двойной клик | На клиенте кнопка блокируется, пока запрос в пути. На сервере один атомарный `INSERT … WHERE NOT EXISTS (тот же номер за 10 минут)`, поэтому даже параллельные запросы не создают вторую заявку (есть тест на 8 одновременных). Номер сравнивается после нормализации. На повтор человек видит «Заявка уже у нас», а не ошибку. |
| Откуда клиент | Сохраняются `utm_source/medium/campaign/content/term`, `yclid`, `gclid`, `fbclid`, внешний referrer, страница входа и страница отправки. Модель «последний рекламный переход»: метки лежат в `localStorage` 30 дней и не теряются, если человек вернулся напрямую. |
| Неудачная отправка | Введённое остаётся в форме, ошибки показываются под полями. При сбое сервера (503), обрыве связи или таймауте (15 с) показывается сообщение, что произошло и что делать, плюс адрес мастерской как запасной путь. |
| Что заказать | В карточках счётчики, в форме «листок заказа» с количеством, суммой и кнопкой «убрать», на телефоне нижняя полоска «В заявке». Уходит `items: {sku: количество}`. Сервер проверяет sku и количество (0–20) и считает сумму по своему прайсу `kvarta/catalog.py`: цены из браузера не принимаются. Тест сверяет цены на странице с каталогом. Корзины и оплаты нет, менеджер уточняет при звонке. |
| Подписка | Один тариф, как в брифе: 2 пачки по 250 г, 54 BYN. В режиме подписки «листок заказа» превращается в «Выберите 2 пачки»: только зерно, счётчик «1 из 2», третью пачку добавить нельзя. У разового заказа и у подписки отдельный выбор, при переключении ничего не теряется. Сервер проверяет то же (`subscription_problem`). Интерес заранее не выбран: кофе из каталога сам ставит «Разовый заказ», кнопка в блоке подписки ставит «Подписку». |
| Вопрос | Форма ровно как в ТЗ: листок заказа скрыт, в комментарии подсказка для вопроса. Комментарий не обязателен: человек мог выбрать «Вопрос», чтобы спросить по телефону. Если с вопросом всё же пришли позиции, сервер молча их отбрасывает и принимает заявку. «Добавить» в каталоге при «Вопросе» переключает на «Разовый заказ». |
| Спам | Скрытое поле-ловушка: боту отвечаем «успех», в базу ничего не пишем. |

**Ответы API:** `201 created`, `200 duplicate`, `422 invalid` (с ошибками по полям), `503 error`.

## Как менеджер видит заявки

- **Telegram** (`kvarta/telegram.py`): каждая новая заявка приходит в чат. В сообщении интерес, имя, телефон, комментарий, источник, объявление, страница входа и время по Минску. Дубль повторно не отправляется. Если Telegram недоступен, форма всё равно работает: заявка к этому моменту уже в базе.
- **CSV для Excel:** `python tools/export_leads.py leads.csv`. Время по Минску, источник разложен по колонкам, есть защита от формул в полях, которые вводит посетитель.
- **Консоль Turso:** таблица `leads`.

## Безопасность и данные

- В логи не попадают имя, комментарий и полный номер (номер маскируется), а также токен Telegram (INFO-логи `httpx` заглушены).
- Страница `/privacy.html` описывает, что сохраняется и как удалить. Это черновик, клиенту нужно согласовать его с юристом.

## SEO и превью ссылок

- `<title>` и description под запросы «свежеобжаренный кофе в зёрнах Минск», «доставка». Один `h1`, дальше иерархия `h2`/`h3`.
- schema.org `Store`: адрес, часы, цены, каталог. Телефона и координат нет, их нет в брифе.
- `robots.txt` (закрыт `/api/`), `sitemap.xml`, canonical.
- Open Graph с картинкой 1200×630 (исходник `tools/og.html`), favicon SVG, apple-touch-icon.
- После деплоя адрес подставляется командой `python tools/set_domain.py https://…`.

## Допущения (в брифе не было)

- Заказ к ближайшей пятнице принимается до конца среды.
- Стоимость доставки для заказа меньше 50 BYN называет менеджер.
- Телефона и Instagram в брифе нет. В подвале стоит заглушка `+375 (29) 000-00-00`: заведомо несуществующий номер, его отклоняет и наша же валидация. При ошибке формы сайт предлагает мастерскую, а не этот номер.
- Сорта для подписки обсуждаются с менеджером при звонке. Способ оплаты тоже.
- Фото не «Кварты»: снимки с Wikimedia Commons (CC BY-SA / CC0) с подписями и авторами в подвале. Места под фото мастерской помечены `TODO`.
- Календарь на первом экране считается по минскому времени.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements-dev.txt
uvicorn app:app --reload          # сайт и API на http://127.0.0.1:8000
pytest                            # 61 тест
```

Без переменных `TURSO_*` заявки пишутся в `data/leads.db`. Все переменные перечислены в `.env.example`. На Vercel они задаются в Settings → Environment Variables:

- `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` — база заявок;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — уведомления (необязательно).
